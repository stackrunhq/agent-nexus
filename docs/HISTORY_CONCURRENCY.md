# 多租户与检查点查询实测

步骤 49（2026-09-15），数据库保持 0015。

运行 `python -m agent_nexus_cli.history_concurrency --rows 2000 --rounds 10 --output result.json`，设置 `NEXUS_TEST_POSTGRES_URL` 指向允许 CREATE DATABASE 的测试服务器。命令只写入随机新建数据库，结束时清理；每租户行数允许 100–20000，轮数 1–100。

原生 PostgreSQL 17.11：四租户各 2000 条任务，25% processing，每个 processing 任务 8 个批次，共 2000 个检查点和 16000 个批次。分别运行 1/4 个读取线程，每线程十次，每次轮换租户；逐页断言任务 ID 与预期完全一致、saved_batches 精确为 8 或 0。任务状态与批次仅为合成查询数据，不执行模型或真实 Worker，也不代表生产准入配额。

真实查询计划发现原先全局 GROUP BY 扫描所有 16000 批次，再连接本租户任务。现改为相关子查询按 job_id 统计，使用现有批次复合主键；实测计划读取 21 个候选任务，执行 21 次批次索引查询，没有全表聚合。21 包含用于判断下一页的一条额外记录。无须迁移或新增索引。
