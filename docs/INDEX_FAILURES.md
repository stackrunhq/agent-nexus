# 索引失败诊断

步骤 45（2026-09-15）：管理端“模型选择与索引管理”增加失败原因筛选与中文处理建议。选择 embedding 模型后，可以查看全部已加载任务、全部失败任务或某个精确错误码的失败任务。

当前接口仍是管理员 `GET /api/v1/admin/tenants/{tenant_id}/applications/{app_id}/versions/{version_id}/index-jobs`，返回该版本最近 20 条任务。页面再按所选模型和失败原因筛选，因此不是完整历史；空结果只表示本次加载范围内没有匹配记录。刷新保留原因选择，切换模型后重新选择。

建议覆盖模型超时/不可达/限流、模型日额度、凭据和授权、响应格式、向量维度变化、内容变化、容量、检查点及 Worker 中断。未知或缺失错误码使用通用排查建议，同时保留原始错误码和任务编号供管理员定位。不读取或显示底层异常正文，不从错误码推断必然的根因。

失败任务不会自动重试。先按建议处理，再通过既有“建立或重建索引”确认流程提交；新任务继续受到配额限制，模型调用可能产生费用。失败保留旧索引，但内容或配置变化后旧索引可能已失效。

本轮仅增加管理页面功能，数据库保持 **0014**，不增加接口或改变队列领取规则。下一步扩展服务端任务历史分页和筛选，避免最近 20 条记录不足以定位历史失败。
