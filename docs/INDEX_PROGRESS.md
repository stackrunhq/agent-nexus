# 内容修订计数与独立批次存储

步骤 34（2026-09-14），当前数据库 **0012**，共 **22 张业务表**。

## 内容修订计数

`knowledge_content_revisions` 按产品版本保存计数。文档解析成功写入分片、实际发布或撤回时，在同一事务内原子增加；重复设置相同发布状态不增加，事务失败则一同回滚。未发布文档解析完成也会增加计数，可能保守地中止同版本构建。

构建开始时记录计数并读取完整内容快照，再确认计数没有变化。每批之间仅查询计数、检查企业/应用/版本可见性、模型授权与模型配置，不再重新加载全部分片。完成后仍做完整内容校验及修订检查，最终保存事务内再次确认内容计数和可见性。该优化针对构建批次；检索和索引状态读取的全文校验尚未改造。

检查点绑定「修订计数 + 内容 SHA256」和模型摘要。即使文档撤回后重新发布、全文恰好一致，也不复用旧修订进度。计数用于业务 API/Worker 的受控写入；直接改数据库不会自动触发计数，不属于支持的内容更新方式。

## 独立批次

`knowledge_index_checkpoints` 保留修订及维度头信息，原 payload 字段保持空数组以兼容表结构；新表 `knowledge_index_batches` 以任务 ID 和起始分片序号为联合主键，每行保存最多 16 个向量。

新批次追加时验证有效租约、修订、维度、连续性和累计大小，只插入新行。恢复时按序读取并校验连续性，成功/失败清理先删除批次，再删除检查点头；最终索引及任务状态仍原子提交。全量向量仍会在最终保存时组合成兼容快照，不代表最终存储已经完全流式化。

## 升级与恢复

先备份，停止 API、解析 Worker 和索引 Worker，使用既有数据库连接配置执行：

```sh
python -m agent_nexus_cli.database upgrade
```

0012 新建两表，**清除旧格式未完成检查点**，保留任务和已完成索引。旧任务重新领取时从头构建一次，可能再次产生模型用量。已有已完成索引继续可用，无需统一重建。新修订计数缺省为 0，第一次受控内容修改时创建并递增。

备份恢复需包含全部 22 张业务表。运行角色需要新表 SELECT、INSERT、UPDATE、DELETE 权限。完成迁移及授权后再启动所有进程；回退应恢复验证过的备份。
