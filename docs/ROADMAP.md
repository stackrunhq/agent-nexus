# 分阶段执行方案

每阶段产出可启动、可测试的闭环，再进入下一阶段。业务模块仅通过统一模型网关调用模型。

## 01 项目基础与统一模型网关（当前已扩展到 0.2）

交付：FastAPI、模型配置管理 API、模型列表、文本对话、向量、请求 ID、统一错误、角色令牌、Docker 与原生部署配置。

适配云端兼容协议、vLLM 等本地兼容协议、Ollama 原生协议。通过别名区分部署位置和能力，密钥使用环境变量引用。

0.2 增量：内置轻量管理页面、配置编辑及启停、管理员能力试调用、耗时/用量展示、兼容接口 token 参数映射、temperature 能力拒绝、总时限和响应大小约束。旧配置自动使用兼容默认值，无需数据迁移。

当前轻量页面随 API 部署，下一阶段的企业级 React 后台仍未实现。

已追加配置变更审计 API 和工作台日志查询。代码开发过程按 CONTRIBUTING.md 分步骤更新 CHANGELOG.md 并创建本地 Git 提交，不推送远端。

已加入配置 ETag 条件写入，防止多个管理员页面互相覆盖；此能力属于进入企业后台前的配置管理加固，企业用户体系与 PostgreSQL 仍在下一阶段。

验收：切换别名调用不同协议；能力不符及禁用模型不请求上游；异常不泄露原始响应；配置重启保留；自动化协议测试通过。真实模型及 Docker 运行验证单独记录，不以模拟测试代替。

## 02 企业与后台基础

0.3 已先实现企业机器凭据、模型授权/撤销、停用、轮换和调用层授权 API，详见 TENANT_ACCESS.md。用户/角色、企业页面和文档数据隔离尚未完成。当前整体状态见 STATUS.md。

数据库增量已交付 SQLAlchemy 存储、Alembic 0001、旧 SQLite 导入、PostgreSQL Compose 与 CI 集成测试；本机无数据库服务，实际 PostgreSQL 测试尚未执行。下一步先完成实库验证和备份恢复，再推进企业页面与用户/角色。

2026-09-09 更新：独立 PostgreSQL 17.11 实库及备份恢复已完成，61 项测试全部通过；同时验证受限运行角色。下一步推进企业页面与用户/角色，生产备份策略及部署账户分离仍单独跟进。

依赖 01。交付 PostgreSQL + Alembic、企业/客户组织/用户/角色、应用及版本、管理员登录、React + TypeScript 后台、模型配置页面和试调用。

当前配置导入 PostgreSQL；增加 secret 引用服务、修改审计、企业模型可见性及额度。全局调用令牌替换为服务凭据/用户短期令牌，企业身份从可信认证上下文取得。

验收：A 企业无法列出或调用 B 企业模型及应用；用户不能管理后台；数据库和后台任务的租户隔离测试通过。完成前不接入真实多企业私有数据。

## 03 知识库与 RAG

依赖 02。交付 S3 存储、Redis/Celery、PDF/Markdown/DOCX 解析、必要的 OCR、切片来源、版本发布撤回、向量及中文关键词索引、混合检索、引用回答。

索引绑定 embedding 模型和版本，换模型先重建再切换。模型不能突破检索权限，文档指令视为不可信资料。

验收：至少 100 个真实问题，核验出处和版本；测试未知问题、越权、撤回和更新中断恢复。

## 04 用户使用指导

依赖 03。交付帮助中心、会话、SSE、断线恢复、iframe SDK、反馈、真实页面入口和截图、分步指引。

验收：小白根据手册完成业务任务；刷新后恢复步骤；浏览器不持有企业长期密钥。

## 05 可控业务流程

依赖 04。交付审核流程模板、计划及状态机、参数校验、只读/写入工具、用户确认、业务审批、幂等、回调验签、未知结果查询及补偿。

先完成一个真实应用的“查询 → 创建草稿 → 确认 → 提交 → 查询结果”。模型建议调用，后端决定授权；不接受任意 URL、SQL 或代码执行。

验收：超时及重复回调不产生重复订单；重启恢复；越权不调用业务端；等待审批不误报完成。

## 06 上线运维

依赖 02–05。交付审计、成本用量、配额限流、观测告警、CI/CD、锁定依赖和镜像、安全扫描、备份恢复、升级文档及 Kubernetes 清单。

先单企业试点再扩展。首个完整试点预算约 9–13 周（1 前端、2 后端/AI，配合产品和测试），依实际资料与接口调整。
