# 多管线并发与进程树内存

步骤 39（2026-09-14）。使用本机专用 PostgreSQL，账号需创建数据库和安装 pgvector 的权限。

```sh
python -m agent_nexus_cli.pipeline_concurrency --postgres-pid 12345 --output evaluation/results/pipeline-concurrency-local.json
```

通过 `NEXUS_TEST_PGVECTOR_URL` 配置本机测试服务器；`--postgres-pid` 必须是该专用实例的主进程 PID，可从其数据目录 `postmaster.pid` 第一行读取。远程数据库、容器 PID 命名空间或其他实例的 PID 不适用于本采样。工具不会根据 PID 停止数据库；实例启停由外部环境负责。

工具依次运行 2、4 个管线子进程，每个使用独立随机数据库、128 分片、64 维模拟模型，完整执行解析、索引、取消后恢复、检索问答和并发配额检查。每类查询采样 3 次。进程分别启动，没有阶段屏障，因此结果表示管线生命周期重叠，不保证每个阶段同步开始，也不验证同一数据库任务队列的竞争。

输出文件会被覆盖，目录需存在。正常结束清理自建数据库；失败时终止尚在运行的自建管线及当前子进程，再清理数据库。硬杀基准主进程或操作系统崩溃仍可能留下临时资源，需要管理员检查专用测试实例。

## 内存分组

- pipelines：管线启动器及管线报告的实际 Python PID，避免 Windows 虚拟环境启动器被误分组。
- parser_descendants：实际管线 Python 进程的后代，本基准中为解析进程及其启动器。
- postgres_tree：指定 PostgreSQL 主进程及当前后代。

每轮枚举进程并采样 RSS/工作集后等待 20 ms，实际间隔还包含枚举及读取成本。进程退出或无法读取会计入遗漏次数。每组取同一轮成员 RSS 之和的最大值；不同组的最大值不一定同时发生。共享内存页可能在多个进程中重复计算，不能把这些值加起来当作物理独占内存。

| 2 | 2.63 | 203.43 | 32.71 | 265.48 |
| 4 | 2.71 | 406.74 | 67.01 | 407.55 |

六个管线均通过所有断言，恢复首批 16 分片并成功结束。两组各记录 2 次退出/不可读进程采样；解析进程数在 Windows 包含启动器。测量区间包括数据库创建、进程启动和场景执行，不包括最终数据库删除；不是单次查询延迟或持续吞吐量。

这仍是短时、独立数据库、模拟模型基准，不能外推真实模型或多租户生产容量。当前 128 分片上限保持。下一步在同一数据库验证多租户 Worker 竞争、任务公平性与持续负载，再讨论扩容。
