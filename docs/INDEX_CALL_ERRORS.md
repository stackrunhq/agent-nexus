# 调用错误码筛选与失败统计

步骤 56（2026-09-16），数据库保持 0017，无新迁移。

任务详情接口新增可选 `call_error`（最多 200 字符），按错误码精确匹配，不进行模糊搜索。省略表示不限错误码，空字符串表示失败调用缺失错误码（NULL）。提供此参数会同时限定 failed；与 succeeded/pending 组合返回空明细。可以继续与 attempt、offset、limit 组合，筛选先于分页，鉴权与租户隔离不变。

summary 新增 `failure_reasons`，每项包含 attempt、error、calls。只统计全任务精确关联且状态为 failed 的调用，按尝试次数、错误码分组；缺失尝试或错误码保留 null。请求匹配记录、成功和 pending 调用不计入该失败分组。汇总不受明细筛选或分页影响，不能将调用失败次数当作任务失败次数。

页面支持输入调用错误码、仅缺失错误码、清除筛选，并明确显示生效条件。输入框空白提交表示不限错误码的失败调用；缺失值须点专用按钮。失败统计显示原始码及现有中文排查建议；未知码采用通用建议。点击“查看此类失败”设置该尝试、failed 和对应错误码并回首页，旧请求取消。选择汇总中的全部/失败调用入口会清除之前的错误码条件。

全任务统计只计算精确归属；手动不选择尝试时，明细仍按原接口包含可能的请求匹配，逐条保留归属标签。点击失败分组使用指定尝试（含 unknown），因此只查询精确关联调用。状态与统计仍实时更新，不保证跨 SQL 快照。
