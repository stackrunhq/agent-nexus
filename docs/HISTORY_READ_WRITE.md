# 检查点读写竞争验证

步骤 50（2026-09-15），数据库仍为 0015，未修改生产接口或连接池配置。

复现：设置 `NEXUS_TEST_POSTGRES_URL` 后运行 `python -m agent_nexus_cli.history_concurrency --mixed-writes --rows 2000 --rounds 10 --output result.json`。沿用随机新建数据库与退出清理机制，仅使用有 CREATE DATABASE 权限的测试服务器。

先执行既有四租户静态读取基准，然后在同一隔离数据库中将测试连接池限定为两连接、零溢出、等待上限五秒。四读线程和一写线程使用分阶段屏障协调；每轮切换租户，对该租户最新任务执行：重置为 processing 并清理、保存第一批、追加第二批、完成/失败并清理。保存和完成调用生产 `IndexCheckpoint.save` / `IndexJobs.finish`；重置阶段是基准准备动作，不是生产重试接口。

读取分三类：与写入阶段同时启动的读取、提交后的精确读取、其他租户读取。校验 processing 的批次计数处于 0–2、终态计数为 0，提交后的阶段计数精确匹配，页面 ID 始终属于指定租户且顺序正确。屏障保证提交后验证结束才进入下一阶段，任意线程失败会中断其他线程的等待。

本机短测使用合成向量，不调用模型，也不测试 Worker 崩溃、真实索引提交或网络故障。线程同时启动不保证每条 SQL 都与写事务重叠；结果不能证明所有调度情况或生产尾延迟。两连接限制只作用于基准，不改变应用默认值。
