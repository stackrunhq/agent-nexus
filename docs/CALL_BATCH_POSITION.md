# 索引调用的尝试与批次定位

步骤 53（2026-09-16），数据库 **0017**，仍为 24 张业务表。

模型调用账本新增可空整数 `index_attempt`、`index_batch_start`、`index_batch_size`。后台领取和同步构建使用该次任务的 attempts 快照；每次实际向量调用保存分片起始位置与本批数量，pending、成功、失败记录共享相同定位信息。

详情 API 的调用记录返回三个字段。`index_batch_start` 从 0 开始，页面显示为从 1 开始的分片区间，例如 start=16、size=3 显示“分片 17–19（3 个）”。这是本次构建快照中的位置，不是手册页码、文档编号或持久分片 ID。

断点复用的批次不产生新的模型调用记录。重领后 attempts 增加，新调用保留新尝试次数；内容或模型变化引发全量重建时，新尝试可以再次从 start=0 开始。比较不同尝试的位置不能假定对应原文完全相同。

位置数据须成组提供且必须有任务 ID，尝试范围 1–3，start 为 0–127 内的 16 倍数，size 为 1–16 且末尾不超过 128；不合法组合拒绝写账本。字段仅由内部构建路径传入，对外提交 API 不接收定位参数。

0017 只增加可空列，不修改旧记录，不根据任务当前尝试次数回填历史调用。旧记录及非索引调用显示“尝试与批次位置未知”。精确任务关联和请求匹配的区别继续保留，未知 token 不按零处理。

## 升级

先备份并停止 API 和全部 Worker，执行 `python -m agent_nexus_cli.database upgrade` 至 0017，再统一启动。迁移不新增表或重建业务索引；备份恢复包含新列，回退使用验证过的备份。SQLite 无版本开发库兼容历史校验，PostgreSQL 仍需显式迁移。
