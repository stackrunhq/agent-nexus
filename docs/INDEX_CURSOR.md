# 任务历史游标与查询索引

步骤 47（2026-09-15），数据库 **0015**，仍为 24 张业务表。

任务列表响应新增 `next_cursor`：有下一页时返回续查位置，否则为 null。下一页沿用相同企业、应用、版本、模型、状态和错误码参数，并传 `cursor`，不传非零 offset。原有 offset 接口保留兼容。

游标最多 1024 字符，记录最后一条的创建时间和 ID，以及查询条件摘要；无效格式、条件变化或与非零 offset 混用返回 422。游标不是凭据，不加密也不授权；接口始终独立校验管理员和资源范围。客户端应原样使用，不自行构造。

排序保持创建时间倒序、ID 升序。后续页仅读取位置之后的数据，避免头部插入导致 offset 位移；锚点任务删除后仍可续查。同秒新任务若排序在当前位置之后仍可能出现，状态筛选也实时变化，因此这不是一致性快照。查看新任务请回首页刷新。页面用游标栈支持上一页，筛选变更清空位置。

0015 新增 `ix_index_history_scope` 和 `ix_index_history_model`，覆盖企业/应用/版本以及可选模型的排序查询。状态和错误码仍是附加过滤条件；本轮不声称所有组合或百万级数据已达到性能目标。

升级前备份并停止 API 和全部 Worker，使用迁移账号执行 `python -m agent_nexus_cli.database upgrade` 至 0015，再启动。只增加索引，不新增表或修改任务内容。索引建立需要磁盘和执行时间，当前使用普通建索引，应在维护窗口运行；回退使用验证过的备份。备份恢复应包含新索引。
