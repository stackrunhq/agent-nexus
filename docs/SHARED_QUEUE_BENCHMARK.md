# 同库多租户 Worker 基准

步骤 40（2026-09-14），数据库保持 0012。

```sh
python -m agent_nexus_cli.shared_queue_benchmark --output evaluation/results/shared-queue-local.json --waves 10
```

通过 `NEXUS_TEST_PGVECTOR_URL` 提供专用测试服务器，账号需创建数据库和安装 pgvector 的权限。每种 Worker 数量使用一个新建随机数据库，结束后删除自己创建的数据库。输出目录需存在，指定文件会被覆盖。`--waves` 支持 1～50；工具不会修改原数据库中的业务配置。

每组在同一数据库创建 4 个租户，每个租户 2 个版本，每个版本含 16 个已解析分片。逐轮提交 8 个后台索引任务，并重复提交确认活跃任务复用同一 ID；分别以 1、4 个异步 Worker 消费共享队列。数据库读写在工作线程中执行，模型使用 64 维固定向量和 5 ms 异步延迟，不调用真实服务。

检查所有任务恰好领取一次、成功且 attempts=1、没有遗留检查点，最后逐版本执行原生 pgvector 检索，确认结果只引用该版本文档。记录每轮消费时间、每租户完成数量和最长领取等待时间。等待时间从该任务第一次提交前计时，包含其他任务提交期间的等待；每轮时间仅含消费，不含提交和环境准备。

## 公平性范围

这是均衡、有限、分轮负载；每轮等待队列清空再提交下一轮。当前调度按 `created_at, id` 排序，时间戳精度为秒，没有租户轮转或权重调度。均衡场景全部完成只能说明本场景没有遗漏或饥饿，不能证明不均衡持续流量下公平，也不等于长时间稳定性测试。

下一步增加不均衡租户负载、持续入队及等待上限检查，再评估是否需要租户轮转。当前继续保留 128 分片上限。
