# 索引元数据与向量内容分离

0010 新增 `knowledge_vector_metadata`，业务表共 19 张。记录版本/模型、配置与内容指纹、维度、分片数和向量 JSON 摘要；`knowledge_vector_indexes.payload` 继续保留完整可移植向量。

索引状态查询读取小型元数据。pgvector 检索使用元数据摘要及分片数定位派生缓存，正常路径不读取或解码完整向量 JSON；portable 检索仍读取完整向量用于本地计算。原生缓存接口 `rank_snapshot` 接受摘要和分片数，原 `rank` 包装保留供合成基准使用。

构建时，元数据、可移植向量、原生缓存（如启用）、任务成功状态都在同一事务内更新。业务 API 返回格式不变，授权和已发布内容校验保持不变。不要单独编辑或恢复元数据表，否则会破坏一致性。

## 升级与兼容

备份后停止 API、解析 Worker、索引 Worker，运行 `python -m agent_nexus.db_cli upgrade`。0010 从已有向量快照逐条回填元数据，不调用模型，不消耗模型额度；JSON 损坏会使迁移失败，应先检查备份与原数据。原生缓存摘要算法不变，正常升级无需重新调用 embedding。

未登记版本的旧 SQLite 或旧 SQLite 导入缺少元数据时，系统保留从原快照计算元数据的兼容读取；这一路径仍会加载 JSON，执行显式升级/重建后才获得性能收益。备份恢复包含新表，受限运行角色需其读写权限。

本轮不迁移原 JSON 到新物理向量表、不提高 128 分片上限。系统仍读取已发布文本计算内容指纹；端到端容量瓶颈尚未完全消除。下一步优化文档版本指纹与分批索引流程，再进行容量基准。
