# 企业调用凭据与模型授权（0.3）

这是模型 API 的企业接入基础，不是完整企业知识库隔离。当前存储支持 SQLite 和 PostgreSQL（17.11 已实测，见 DATABASE.md），尚无企业员工、角色、应用、文档或会话数据模型。

## 启用

设置 `NEXUS_AUTH_MODE=tenant` 后重启 API。Docker 修改 `.env` 后运行 `docker compose --project-directory . -f docker/compose.yaml up -d --force-recreate api`；如需新代码先加 `--build`。

- tenant：调用接口只接受数据库中启用企业的有效密钥，忽略 NEXUS_CLIENT_TOKEN。管理员令牌只管理后台，不可调用用户接口。
- bootstrap（默认）：保留原开发模式，全局调用令牌可访问全部启用模型，企业密钥不用于调用认证。可以先配置企业，再切换 tenant。
- 非法模式启动失败。tenant 模式可留空 NEXUS_CLIENT_TOKEN，管理员令牌始终必填。

工作台连接后展示当前模式，避免误认为开发模式已具备企业隔离。

## 操作顺序

在 `/docs` 使用管理员令牌：

1. 按现有流程配置模型，例如 `local-help`。
2. `POST /api/v1/admin/tenants`，正文 `{"name":"示例企业"}`。返回企业 id 和一次性展示的 api_key；妥善保存于企业服务器，不放入浏览器脚本。
3. `PUT /api/v1/admin/tenants/{id}/models/local-help`，无需正文，授予该模型使用权。
4. 切换 `/docs` 的授权为企业 api_key，调用 `GET /api/v1/models`，应只看到已授权且启用的模型。
5. 继续调用原对话/向量接口，正文格式不变。企业身份来自密钥，不接受正文提供的 tenant_id。

新企业默认没有模型权限。未授权模型返回 403，且不会请求上游模型。

## 管理接口

| 方法与路径（统一前缀 /api/v1/admin/tenants） | 用途 |
| --- | --- |
| POST / | 创建企业；返回一次性 api_key |
| GET / | 企业列表；无密钥或摘要 |
| PATCH /{id} | 正文 {"enabled":false} 停用；true 恢复 |
| POST /{id}/rotate-key | 替换密钥；仅返回新密钥，旧密钥立即失效 |
| GET /{id}/models | 查看授权别名，包括暂时禁用的模型 |
| PUT /{id}/models/{alias} | 授权已有模型；重复授权无副作用 |
| DELETE /{id}/models/{alias} | 撤销授权；重复撤销无副作用 |
| GET /{id}/events | 最近 100 条企业接入事件 |

集合路径实际为 `/api/v1/admin/tenants`，没有末尾斜杠。所有管理接口仅平台管理员可用，企业不能自己授权。

## 凭据及授权边界

- 服务端生成 256 位随机密钥，数据库保存 SHA-256 摘要；高熵机器凭据不等同于用户密码。
- 每企业当前只有一个有效密钥。创建/轮换响应丢失时不能取回明文，需要再次轮换。轮换不自动启用已停用企业。
- 撤权、停用及轮换对后续请求生效，不取消已进入模型生成的请求。
- 企业接入事件记录创建、启停、轮换、授权及撤销，不记录密钥；变更和事件同事务。当前最近事件接口未提供分页和个人操作者身份。
- 管理试调用仍是平台管理能力，不代表企业有权限调用。
- 授权绑定模型别名，平台管理员可修改别名对应配置；本阶段不包含企业数据出境策略或对渠道重绑定的独立审批。
- 没有企业配额、到期时间、多密钥、SSO、员工角色或 PostgreSQL 行级隔离。不能把本能力视为完整多租户生产方案。
