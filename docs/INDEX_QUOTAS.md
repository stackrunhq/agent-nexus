# 索引构建配额

## 企业差异化配置（0007）

管理员 `GET/PUT /api/v1/admin/tenants/{tenant_id}/index-quota` 读取或替换企业配置。PUT 请求示例 `{"daily_limit":200,"active_limit":10}`；每日允许 0–100000，活跃允许 0–100。字段为 null（或省略）表示继承默认值，因此 PUT 必须携带想保留的两个字段。响应同时返回 effective_daily_limit、effective_active_limit。

界面入口：知识库 → 向量索引与检索 → 设置企业索引限额。保存需确认，0 会阻止新任务但不取消已有任务；后台重复提交仍可复用已有任务。降低限额不会清空日用量。多人编辑采用最后一次保存生效，可先重新读取。

配置存储在 tenant_index_quotas，与任务准入共用事务锁；修改写入企业事件（含操作者、请求 ID 和新值）。数据库必须从 0006 升级到 0007，业务表共 16 张。环境变量现在只作为未覆盖企业的默认值。实际模型调用账本与 token/费用限额仍未实现。

同步 `POST /vector-index` 与后台 `POST /index-jobs` 共用任务登记、活跃数和每日额度检查。旧同步接口仍返回索引结果；如已有相同版本/模型的活跃任务，返回 `409/index_job_active`，不会重复调用模型。后台重复提交则返回已有任务。

默认每企业每日 **100 个新建任务**，同时最多 **5 个活跃任务**。部署变量 `NEXUS_INDEX_DAILY_LIMIT` 可设置 1–100000，未设置企业覆盖值时使用该默认值；所有 API 副本必须保持相同配置。Compose 已传递该变量。每日按 UTC 零点重置，界面显示本地重置时间。

配额检查和任务插入处于同一数据库锁/事务内，并发不能越过上限。额度跨应用、版本和模型共享。已完成或失败任务都计数，复用任务和租约恢复不重复计数。无效参数、未授权模型或超容量资料在登记前拒绝，不计数。任务创建日期决定其所属日，排队跨日执行仍计入创建日。

管理员查询 `GET /api/v1/admin/tenants/{tenant_id}/index-usage`：

```json
{"daily_limit":100,"daily_used":2,"active":1,"active_limit":5,"reset_at":1789084800}
```

超日额度返回 `429/index_daily_quota_exceeded`；活跃任务达上限返回 `429/index_queue_full`。页面刷新索引状态时显示用量。数据库为 0007；现有任务历史也参与当日计数，不能删除任务历史来“清理”用量。

这是**任务准入额度**，不等同于实际请求次数、token 或费用。一个任务可能分批调用 embedding，异常恢复最多尝试 3 次；检索/问答调用不纳入本轮额度。同步请求中断后，租约到期可由索引 Worker 恢复，客户端超时不能理解为任务取消。
