# 索引批次检查点

当前实现已升级至 0012：使用内容修订计数与独立批次表，旧格式未完成检查点在升级时清理。请先阅读 [当前存储与升级说明](INDEX_PROGRESS.md)，以下保留 0011 基础设计记录。

步骤 33，2026-09-14。数据库版本 **0011**，共 **20 张业务表**。

## 已实现

后台索引 Worker 每完成一批（最多 16 个分片）就将归一化向量写入 `knowledge_index_checkpoints`。检查点以任务 ID 为主键，保存内容 SHA256 修订标识、模型配置摘要、维度和已完成的向量前缀，不保存手册正文。检查点属于内部数据，不提供下载接口，也不能被检索。

进程中断后，任务保持 processing；300 秒租约过期后，新 Worker 可以重新领取。它重新验证企业、应用、版本、模型授权和当前内容。内容与模型摘要一致时跳过已完成批次；任一摘要变化则清除旧进度，从头构建。修订标识描述内容快照，不是单调递增的发布历史版本号。

检查点读写通过任务行的条件更新验证有效租约及领取令牌，并锁住任务行直到事务结束。被替换的旧 Worker 无法读取、覆盖或删除新进度。完整索引、元数据、pgvector 缓存、任务成功和检查点清理在最终事务中一起提交；中间结果不会覆盖旧索引。

普通模型错误、授权撤销等终止失败会清理检查点；连续三次进程中断后任务终止并清理。自动恢复仅用于被中断后重新领取的同一个任务，手动新建任务不会复用其他任务的检查点。同步接口保持兼容，不保存逐批检查点。

## 部署升级

备份后停止 API、解析 Worker 和索引 Worker，再使用迁移账号执行既有数据库升级命令：

```sh
python -m agent_nexus_cli.database upgrade
```

按现有部署配置提供数据库连接。运行账号需要新表的 SELECT、INSERT、UPDATE、DELETE 权限；备份恢复必须包含该表。迁移不改变已完成索引，无需重新调用模型。升级后再启动全部进程。回退应恢复验证过的备份，不执行破坏性 downgrade。

## 当前边界与下一步

- 保持 128 分片、4096 维及 16 MiB 上限，每次构建尝试仍有 120 秒模型阶段超时。
- 上游已返回但检查点尚未提交时崩溃，该批可能重调；已登记的模型用量不会退回。不是 exactly-once 调用。
- 恢复仍读取全文计算内容摘要；每批检查点暂时重写整个已完成前缀。尚未解决大型索引的全文读取和累计写入成本。
- 下一步实现与文档生命周期事务一致的内容修订计数，以及独立批次存储，再做大容量端到端验证；本步不提高上限。
