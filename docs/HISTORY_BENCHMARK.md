# 历史任务查询实测

步骤 48（2026-09-15）。新增 `python -m agent_nexus_cli.history_benchmark --rows 20000 --rounds 5 --output result.json`。设置 `NEXUS_TEST_POSTGRES_URL` 为测试服务器连接，账号需 CREATE DATABASE 权限；命令只在随机新建数据库中迁移、生成任务并查询，退出时删除该数据库，不写入目标数据库的业务表。报告不包含连接凭据。

基准通过生产 `IndexJobs.list` 查询并捕获实际 SQL，记录 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`。单企业/应用/版本、两个模型，2 万条合成终态任务，10% 指定错误；分别在匹配记录的 80% 位置比较 offset 与游标。每项预热一次、测量五次，并断言两种查询返回相同预期任务。检查点为空，没有模型调用。

原生 PostgreSQL 17.11 初次计划发现：版本/模型游标虽用索引，仍分别过滤 16000/8000 条前序记录。添加等价的 `created_at <= anchor` 范围条件后，计划将时间范围纳入 Index Cond，两项过滤均降至 1 条；相同时间的 ID 续查条件继续保留。数据库仍为 0015，无需新增索引。

| 查询 | 优化前游标中位 ms | 优化后游标中位 ms | 本轮 offset 中位 ms |
| --- | ---: | ---: | ---: |
| 版本 | 3.305 | 1.593 | 9.523 |
| 模型 | 2.623 | 1.568 | 6.914 |
| 模型＋失败错误码 | 1.857 | 2.139 | 4.951 |

计时包含数据库读取、范围校验和 Python 序列化，不是 HTTP 耗时；失败筛选短样本存在波动，不能声称全部查询都提速。没有关闭顺序扫描或强制使用索引。原始计划：[优化前](../evaluation/results/history-before-2026-09-15.json)、[优化后](../evaluation/results/history-2026-09-15.json)。

本机热缓存、串行短测，不代表并发、冷缓存、大量活跃检查点或多租户场景，也不提供 SLA。当前不增加状态/错误码组合索引。下一步扩展多租户、活跃检查点和并发查询基准，检查检查点聚合成本。
