# 索引任务历史查询

当前步骤 47 已增加 [游标分页与 0015 查询索引](INDEX_CURSOR.md)，页面使用游标翻页；offset 仍供旧客户端兼容。以下为步骤 46 接口基础说明。

步骤 46（2026-09-15），数据库保持 0014。

管理员接口：`GET /api/v1/admin/tenants/{tenant_id}/applications/{app_id}/versions/{version_id}/index-jobs`。

| 参数 | 规则 |
| --- | --- |
| offset | 默认 0，范围 0–1000000 |
| limit | 默认 20，范围 1–100 |
| model | 可选，精确模型别名，长度 1–200 |
| status | 可选：queued / processing / succeeded / failed |
| error | 可选，精确错误码，最多 200 字符；空字符串匹配缺失错误码的失败任务 |

所有条件先在服务端组合，再按创建时间倒序、任务 ID 升序分页。传入 error 同时限定失败状态；与其他状态组合返回空结果。响应保留 `data`，新增 `offset`、`limit`、`has_more`；多读取一条判断是否有下一页，不执行全量总数统计。仍先校验企业、应用和版本关系，不放宽管理员权限。

管理端选定模型后展示分页历史，支持状态、手输错误码、缺失错误码和清除筛选。筛选变更返回首页，刷新历史回到首页；查询中清空旧行并取消过期请求。重新提交成功后刷新历史，沿用既有提交确认和配额规则。

分页基于实时数据，不是快照。并发新增任务或状态变化可能导致跨页重复或遗漏，需回首页刷新；当前不提供精确总页数或无限深分页。下一步评估游标分页和对应查询索引，改善持续入队下的历史浏览稳定性与大数据量查询。
